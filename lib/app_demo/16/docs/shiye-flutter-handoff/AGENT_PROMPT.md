# 给实现 AI 的任务提示词

把下面整段内容复制给负责 Flutter 实现的 Agent。它假设 Agent 已经能访问本交接包目录。

---

你是一名资深 Flutter 工程师。请在当前仓库中实现一个名为「拾页」的手机端电子手账 App，行为与视觉参照本目录中的 Web 原型资料。

## 必读资料

按顺序阅读：

1. `FLUTTER_IMPLEMENTATION_SPEC.md`（完整规格，最高优先级）
2. `seed/materials.json`（素材目录、分类文案、粘贴默认位置）
3. `seed/entries.json`（示例手账数据）
4. `reference/*.png`（6 张界面截图）
5. `assets/`（全部图片资产，已在本地）

不要访问原始网页，不要从网络重新抓取素材。

## 任务目标

实现三个页面及其完整交互：

- **手账页**：日期头部、心情切换、可拖动的拍立得、贴纸/胶带/便签/照片拼贴、文字编辑、照片上传、撤销、保存。
- **素材抽屉**：贴纸/胶带/便签/照片四类素材，单选、预览、贴到手账，贴纸带飞入动画。
- **翻看页**：月历、有手账日期的缩略页、选中日期的摘要卡、进入任意一天编辑。

## 技术约束

- Flutter 3.24+ / Dart 3.5+，移动端优先（iOS + Android）。
- 空仓库时用 `flutter create --org com.example --platforms=ios,android shiye`；已有工程则遵循现有目录结构与命名。
- 默认使用 Flutter 原生状态管理：`ChangeNotifier` + `AnimatedBuilder`，不引入 Riverpod/Bloc/GetX，除非工程已有明确约定。
- 依赖：`flutter_svg`、`shared_preferences`、`image_picker`、`path_provider`、`uuid`。
- 所有视觉效果用 Flutter 原生能力实现；胶带、纸条、打孔、虚线等用 `CustomPainter` / `ClipPath`，不要用整页截图当背景。
- 文案、颜色、尺寸、圆角、动效时长以规格书为准。规格书第 13 节列出的“原型怪癖”按其中给出的决策处理。
- 不新增原型没有的功能：删除素材、缩放、旋转、图层顺序、登录、云同步、分享、评论。
- 演示时钟默认固定为 2026-10-04，初始化页面为这一天的「有风的下午」；不要直接使用 `DateTime.now()` 作为默认值。

## 实现顺序

1. 工程脚手架、依赖、`pubspec.yaml` 资产注册、设计 token。
2. 数据模型、JSON 种子加载、`shared_preferences` 持久化。
3. `DiaryController`：屏幕状态、当前条目、草稿、撤销栈、保存状态、Toast。
4. Shell + 底部导航 + 全局 Toast。
5. 手账页静态还原（纸张、拍立得、小票、文字、工具条）。
6. 手账页交互：心情、文字弹窗、照片上传、撤销、保存。
7. 素材抽屉 + 四类素材 + 选择托盘 + 贴入与贴纸飞入动画。
8. 拖动（拍立得 + 已贴素材）与边界限制。
9. 翻看页：月历、缩略页、摘要卡、打开任意一天、月份切换限制。
10. 响应式、无障碍、动效降级、单元/Widget 测试。

## 交付要求

- 运行 `flutter analyze` 无 error。
- 运行 `flutter test` 全部通过，至少覆盖规格书第 16 节的单元测试与关键 Widget 测试。
- 在 390x844 与 320x700 两个尺寸自测，确保无溢出、无不可点击区域。
- 输出一份简短实现说明：文件结构、状态流转、与规格书的差异（如果有）。
- 完成后按规格书第 15 节逐条自查。

如果规格书某处与现有工程约定冲突，优先保持产品行为与视觉，工程结构遵循现有约定；有歧义时选择最接近 `reference/` 截图的方案，并在实现说明中记录。
