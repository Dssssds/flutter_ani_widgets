# Flutter 聚会小游戏：AI 编码任务书

## 0. 文档用途与事实边界

这是交给 AI 编码助手执行的工程任务书，不是已完成的 Flutter 工程。

参考视频展示了 10 个游戏入口，完整演示了抛硬币。本文对其他游戏的规则属于首版产品设计，不代表视频中的 App 已实现这些规则。

目标平台：Android、iOS。目标使用方式：多人围着一部手机，本地离线运行。首版不做账号、联网房间、支付、广告、云同步、真实物理引擎。

工程名使用 `party_box`。接入已有工程时保留其包名、状态管理与路由框架，不自动创建嵌套工程或替换现有入口。

## 1. 交付范围与页面数量

完整版本是 11 个独立页面、3 个共享底部弹层。首页两组菜单属于同一个页面，不计为两个页面。游戏内准备、运行、结果属于页面状态，不重复计算页面数量。

## 2. 首轮应交付什么

不要在一次编码中同时创建 11 个空壳页面。

第一批只交付 P01、P02、S01、S02、工程骨架和测试：

* P01 显示全部 10 个游戏入口。
* 只有抛硬币入口启用；其余条目明确显示未开放并禁用，不能进入空白页。
* P02 具有可反复操作的完整动画和状态流程。
* S01 包含震动、标准/快速动画、减少动态效果，不提供没有实现的声音开关。
* S02 支持金色、冰蓝、玫瑰三种硬币配色，不要求外部素材。
* 下一批完成一个游戏后，启用对应入口。

完整交付时不得遗留占位页、未开放入口、无响应按钮。

## 3. 工程技术约束

### 3.1 依赖

优先使用 Flutter SDK：Material、Navigator、PageRouteBuilder、ChangeNotifier、ListenableBuilder、AnimationController、CustomPainter、HapticFeedback。

运行时第三方依赖首版只需要 `shared_preferences`，用于保存设置和参与者名单。由工程实际 Flutter/Dart 版本解析兼容版本，不把未经验证的版本号写死在任务书中。

使用 `flutter_test` 编写测试。随机性来自注入的 RandomSource，正式实现可封装 `dart:math`，测试使用固定序列。不实现涉及真实财产或博彩的玩法。

不引入 Flame、完整 3D 引擎、传感器插件、音频插件、网络请求、代码生成器。声音、摇一摇、倾斜猜词是后续增强，不在此交付范围。未接入的能力不展示为可用开关。

### 3.2 分层

View：布局、手势接入、动画控制器、局部重绘、导航。

ViewModel：不可变页面状态、输入校验、回合开始/结束、待揭晓结果、回合 ID。

Domain：CoinRules、DiceRules、SelectionRules、TeamRules、题库无重复抽取。纯规则不依赖 Widget、BuildContext、Ticker。

Repository：SettingsRepository、ParticipantsRepository、ContentRepository。前两者封装持久化服务；ContentRepository 读取内置题库。

Service：PreferencesService、RandomSource、FeedbackService。FeedbackService 首版只包装震动与开关，不伪装已接入声音。

AnimationController 必须由 View 的 State 创建与 dispose，不放进 ViewModel 或 Repository。ViewModel 不逐帧通知；动画使用 AnimatedBuilder 或 CustomPainter(repaint: ...)。

每个 feature 分成 views 与 view_models。不要把所有页面、规则和 painter 堆进一个文件。不要给简单纯计算强行加 Repository。

### 3.4 导航

首版使用 Navigator 与集中式路由工厂，入口传 gameId 或稳定路由名，未知路由返回明确错误页面及回首页按钮。

所有游戏页顶部关闭按钮执行返回；Android 系统返回同样释放动画、计时器及反馈资源。首页停留时不运行任何游戏动画。

如果已有工程使用 go_router 等框架，沿用该框架，不再增加第二套路由。

## 4. 通用视觉和组件

### 4.1 视觉方向

深色舞台、高对比大字、彩色菜单条目、少量金属质感和圆环反馈。避免把系统默认紫色 Material 页面当最终视觉。

首页底色参考 `#151019`；正文白色；辅助文案使用足够对比度的浅灰。每个游戏拥有一组彩色背景与深色文字。硬币金色可以从 `#FFF7A5`、`#E9C94A`、`#98731B` 起步。

尺寸使用逻辑像素和布局约束，不照搬视频物理像素。内容最大宽度约 600；按钮最小高度 52；常用水平边距 20；圆角约 18。实际以文本缩放、小屏幕测试为准。

### 4.2 组件清单

* GameMenuTile：图标、名称、可用状态、整行点击、按压反馈。
* GameScaffold：关闭、标题、外观入口、舞台、状态区、底部操作区。
* PressScaleButton：按下缩放 0.97、松开恢复，支持禁用与 Semantics。
* GameStage：约束舞台尺寸，隔离重绘边界。
* ResultReveal：结果文字、圆环、结果可访问性播报。
* RoundActionBar：开始、再来一次、下一轮等操作。
* ParticipantsEditorSheet：名单输入、添加、删除、保存、校验。
* GameSettingsSheet：震动、动画速度、减少动态效果。
* AppearanceSheet：三种配色，保存所选外观。
* TimerRoundView：计时游戏的准备、进行、暂停、结算布局。

### 4.3 自适应和可访问性

使用 SafeArea、LayoutBuilder，舞台取剩余可用空间。低高度或大字体时允许内容滚动，不缩小可点击区域来强行塞入。

触控目标至少约 48。系统字体放大时不得裁掉主操作按钮。系统要求减少动态效果时，即使应用开关关闭，也采用减少动态效果模式。

可访问性只在结果真正揭晓时播报，不在每次动画重绘时播报。装饰圆环使用 IgnorePointer，不抢焦点。

## 5. 逐页实现细则

### P01 游戏首页

布局：顶部品牌与 Pick a Game 文案，中间 PageView 两页菜单，底部页码/分页提示及独立设置按钮。

第一页依次为 Headbands、Truth or Dare、Spin the Bottle、Charades、Would You Rather。第二页依次为 Roll the Dice、Coin Toss、Pick One、Elimination、Build Teams。

交互：左右滑动翻页；点击分页提示可翻页；点击可用游戏进入对应路由；点击设置打开 S01。返回首页时保留当前页码。

实现：PageView + PageController；菜单使用整条可点击的彩色容器。常规高度下 Column + Expanded 分配条目；低高度/大字体下每页改为可滚动列表。底部工具栏独立占位，不能遮挡最后一条名称。

反馈：按下 80 ms 缩放至 0.97，松开约 140 ms 恢复。程序化翻页约 300 ms。页面进入使用约 280 ms 淡入与小幅上移。

验收：两个菜单页都可见；返回后页码不丢；快速点击不会叠开多个相同页面；未开放入口明确禁用。

### P02 抛硬币

布局：关闭/标题/外观按钮；中央硬币；提示或结果；底部抛硬币按钮。

状态：idle、running、revealing、result。待揭晓结果单独存储，不提前渲染给用户。

交互：点击硬币或底部按钮均调用 requestFlip。running/revealing 时不能再触发，底部按钮禁用。结果展示后点击任一入口开始下一轮。外观按钮只在 idle/result 可用。

规则：开始时由规则层生成 heads/tails 并分配 roundId；动画按既定结果落点；揭晓事件需校验 roundId；过期回调不更新状态。

实现：单一主 AnimationController 驱动分段时间轴。Transform.rotateX/Matrix4 做翻转，CustomPainter 做金属边缘、渐变面和圆环。根据 cos(angle) 判断可见面，背面额外反向补偿 pi，确保文字不镜像。近侧面必须绘制边缘，不把零厚度图片当完整硬币。

连续性：保存 settledHalfTurns。Heads 对应偶数半圈，Tails 对应奇数半圈。每轮增加至少 6 个半圈，再补足目标奇偶，不能每次重置到正面。

时间轴：0–120 ms 蓄力；120–1450 ms 上抛和翻转；1450–1650 ms 回落停稳；1650–1950 ms 结果入场；1650–2200 ms 圆环消退；2200 ms 解锁。快速模式按同一归一化时间轴缩短至约 1000 ms。

减少动态效果：不连续旋转，用约 200 ms 淡入揭晓；不做大范围圆环。阴影随升高缩小变淡、回落恢复。

离开页面：取消 ticker 和反馈，不触发结果震动。切后台再回来：直接展示已确定结果，不重新抽签、不补播震动。

验收：固定结果测试能分别落到正反面；上一轮反面到下一轮不跳回正面；连点只产生一轮；退出后没有 ticker 或 setState 异常。

### P03 掷骰子

布局：顶栏；1–3 枚骰子舞台；数量选择 1/2/3；合计；投掷按钮。

状态：ready、rolling、result。rolling 时锁定数量和投掷入口。

规则：每枚独立生成 1–6，开始时确定最终点数，合计只使用最终点数。视觉中间帧不改变规则结果。

实现：CustomPainter 画圆角正方形和点数；位移、旋转、缩放产生约 1200 ms 的滚动感。视效按时间或翻面事件切换中间点数，不每帧重建 ViewModel。首版是风格化 2D/2.5D，不承诺真实立方体物理。

交互：更改数量只在 ready/result 生效并清除旧合计；点击投掷开始；结果后同一按钮显示再掷一次。

验收：数量改变正确；每枚值合法；合计正确；动画停止后不继续抖动。

### P04 转瓶子

布局：顶栏；参与者数量与编辑入口；围成一圈的姓名；瓶子；结果；旋转按钮。默认载入 4 个演示参与者，用户可编辑。

人数：2–12。其他名单游戏允许更多人，这一页超过 12 人时需提示缩减，不能悄悄丢弃名单。

交互：准备/结果状态可打开 S03；旋转期间锁定编辑和再次旋转；停止后高亮瓶口指向的人；再点旋转开始下一轮。

规则：先随机选中参与者索引，再计算瓶口目标角度。不能用肉眼接近哪个名字来判结果。

实现：姓名通过 LayoutBuilder + Stack/Positioned 或 CustomMultiChildLayout 环形摆放；瓶子用自绘或内置图形，无外部下载依赖。约 2000 ms 的角度动画，至少转 4 圈后减速。

坐标约定：瓶口初始向上，索引 0 在正上方，顺时针排列。目标方向为 index * 2pi / count，按当前累计角度补齐若干整圈。瓶口、姓名高亮和文案必须使用同一选中索引。

验收：确定索引时方向正确；编辑后布局更新；文字重叠时缩减舞台或采用受约束姓名标签，不裁掉关闭按钮。

### P05 随机选人

此页面首版采用名单抽选，不做多人手指按屏选人。

布局：顶栏；名单编辑入口；姓名标签列表；中间候选人展示；抽选按钮。

人数：2–30。交互：打开 S03 编辑，点击开始后依次高亮候选人，约 1400 ms 后停在选中者；结果后再抽一次。不做跨轮排除，允许重复选中同一个人。

规则：先确定最终参与者 ID；滚动只是表现。编辑名单后清除选中结果。

实现：Wrap 展示标签，AnimatedContainer 切换高亮；中央姓名使用 AnimatedSwitcher。只在高亮索引改变时更新对应 UI，不每帧重建列表。移动减少模式直接淡入最终姓名。

验收：结果一定来自保存的名单；名单变更后无失效索引；连点不重复开始。

### P06 淘汰游戏

布局：参与者名单；存活人数；已淘汰区域；淘汰一人按钮；重置入口。

人数：2–30。状态：setup、running、betweenRounds、finished。

交互：每点击一次随机淘汰一位存活者；约 1000 ms 高亮后移入淘汰区；剩一人时显示胜者，主按钮改为重新开始。开始淘汰后禁用名单编辑，重置后才可编辑。

规则：从存活 ID 集合抽选；每轮人数只减少 1；已淘汰者不能再次被淘汰；剩余 1 人时不可继续淘汰。

实现：不可变 survivorIds/eliminatedIds；AnimatedList 或保持稳定 Key 的 AnimatedSwitcher/AnimatedSize；移动减少模式直接更新分区。

验收：n 人恰好 n-1 轮结束；不会重复淘汰；重置恢复原名单。

### P07 随机分组

布局：名单入口；人数；队伍数选择；开始分组；结果中的队伍卡片；重新分组按钮。

人数：2–30。队伍数：2 到 min(6, 人数)。少于 2 人不能提交。

交互：更改名单或队伍数后清除结果；点击分组后短暂显示混排，再按队伍逐组揭晓；再次点击重新随机。

规则：先洗牌，再 round-robin 分配到各队；每人恰好出现一次；最大和最小队伍人数差不超过 1。队伍只是颜色与编号，首版不做实力平衡或固定搭档。

实现：纯 TeamRules 生成结果；ListView 展示队伍卡片；约 600–900 ms 的轻量淡入，不让大型列表每帧布局。

验收：团队数合法；成员没有重复和遗漏；人数差约束成立；结果可在小屏滚动查看。

### P08 真心话大冒险

布局：顶栏；简短规则；中央卡片；真心话和大冒险两个按钮；换一题按钮；重置本轮入口。

状态：chooseType、showingCard、transitioning。当前题目包含 id、type、text。

交互：点击任一类型抽题并显示；换一题只从当前类型抽取；用户可直接切换另一类型；翻卡期间禁用重复操作。重置清除已抽取集合并回到类型选择。

题库：每种至少 20 条中文种子数据，内容适合一般朋友聚会，不包含强迫饮酒、危险挑战、隐私羞辱或性胁迫。当前类型全部用完后清空该类型已用集合，提示题库已循环；数量大于 1 时避免循环边界连续同题。

实现：ContentRepository + 无重复抽取规则；约 350 ms 翻卡或滑动替换。翻卡使用背面补偿，文字可滚动，不能写死卡片文字高度。

验收：类型正确；用完前不重复；长题目可阅读；没有网络也能玩。

### P09 二选一

布局：顶栏；问题序号；两个大选项卡；选择后的状态提示；下一题；重新开始。

状态：unanswered、answered。首版没有多人投票与百分比，不伪造统计数据。

交互：点击 A 或 B 后固定本题选择；选中卡片轻微放大/描边，另一项变弱；下一题允许跳过并清除本题选择；重新开始清空题目进度。

题库：至少 20 组有稳定 ID 的中文二选一题；全部用完后循环，避免相邻同题。

实现：AnimatedContainer、AnimatedOpacity；选项内容支持换行和滚动。选择反馈约 180 ms，下一题转场约 250 ms。

验收：选择不会自动跳题；下一题清除上次选中；不展示没有数据来源的百分比。

### P10 举手机猜词

首版规则：用户手持手机朝向其他人，其他人给提示。使用屏幕答对/跳过按钮；不做倾斜检测，不暗示已经支持传感器手势。

布局阶段：

1. 准备：规则说明、类别、60/90 秒时长、开始。
2. 进行：倒计时、一个大词条、答对、跳过、暂停。
3. 暂停：冻结词条和倒计时，显示继续或结束。
4. 结算：得分、答对与跳过列表、再玩一次。

词库：至少 3 类，每类至少 20 个，首版类别可采用动物、食物、日常物品。回合内不重复，词库耗尽时提前结束并说明。

规则：答对加 1 分并记录词条，跳过只记录不加分。最后一刻点击必须由状态和剩余时间共同校验，不在结束后继续加分。

实现：使用 Stopwatch 或可注入单调时钟计算已用时间，周期 ticker 只负责刷新显示，不能用每秒自减整数充当唯一计时来源。暂停累计有效时长；切后台自动暂停；返回后必须手动继续。

验收：60 秒时长正确；暂停不消耗时间；结束后按钮无效；结算记录与得分一致。

### P11 你演我猜

复用 P10 的计时引擎和结算组件，但保留独立页面和独立题库。

规则说明改为表演者只能动作表达，不能说出词条。首版类别可采用动作、职业、影视情境，每类至少 20 个。按钮、计分、暂停、后台处理同 P10。

不要复制另一份计时状态机，也不要让两个页面共享同一个活跃回合实例。共享的是规则类与组件，页面会话独立。

验收：题库不同、规则说明不同；离开其中一页不会影响另一页；回合记录相互隔离。

## 6. 共享弹层细则

### S01 设置

入口：首页设置按钮。内容：震动开关、标准/快速动画选择、减少动态效果开关。可以显示简短说明，不提供无实现的声音项。

使用 showModalBottomSheet，SafeArea，内容溢出可滚动。修改立即生效；SettingsRepository 异步保存。保存失败应保留内存设置并显示非阻断提示，不抛未处理异常。

应用启动读取失败时回退默认值：震动开、标准动画、应用减少动态效果关。系统减少动态效果优先。

### S02 游戏外观

入口：P02–P07 顶部外观按钮，运行期间禁用。三种配色预览，选中后立即替换主体强调色并保存。首版使用全局统一外观设置，不为每个游戏另做一套复杂皮肤管理。

关闭弹层不回滚，因为这是即时生效设置。只更新主题颜色，不触发随机结果或重置回合。

### S03 参与者编辑

入口：P04–P07。打开时复制仓库名单为草稿。内容：单行姓名输入、添加按钮、姓名列表与删除、保存按钮。

校验：姓名 trim 后非空；长度 1–12 个用户可见字符；重复名不允许，比较时 trim 并忽略英文大小写；最多 30 人。实现用户可见字符长度时使用 Flutter SDK 可用的 characters 支持，不用 codeUnits 长度冒充字符数。

转瓶子页面提交限制为 2–12 人，其他为 2–30 人。允许临时删除到少于 2 人，但保存按钮禁用并说明。

保存：以稳定 ID 保存参与者列表，按调用页面约束校验后写入仓库、关闭弹层，并让调用页面清除旧结果。关闭、下滑、系统返回：丢弃草稿。

名单是全局最近保存的一份；当前游戏已开始的会话使用自己的不可变快照，不被另一个页面修改。P06 进行中不能编辑。

键盘弹出时使用 viewInsets 调整底部间距；列表可以滚动；保存按钮不能被键盘遮住。

## 7. 动画、回合和生命周期统一约束

### 7.1 动画配置

所有时长集中到 MotionSpec，至少包括 pressIn、pressOut、route、coinRound、diceRound、bottleRound、pickRound、reveal、ripple。

标准与快速版本使用同一归一化时间轴。减少动态效果不是把全部时长设成零，而是切换到短淡入，仍保留明确状态变化。

### 7.2 回合一致性

状态锁定先于异步操作。每次开始创建 roundId。结果先确定并保存在内部，再发动画指令；展示层不能提前泄露待揭晓结果。

动画完成回调传 roundId。ViewModel 忽略失效 ID。避免在 build、paint 中调用震动、持久化或规则抽取。

页面销毁后所有动画 future、ticker、timer 都不得继续提交状态。AnimationController.forward().orCancel 应处理 TickerCanceled，不能让取消变成未捕获异常。

### 7.3 生命周期

随机工具页：进入后台或失去活跃状态后停止反馈；返回时展示本轮确定结果，不重新生成随机数。若动画在后台已完成，也不补播声音或震动。

计时游戏页：失去活跃状态后自动暂停；恢复时显示暂停界面，用户点击继续才继续倒计时。

导航离开页面：直接结束本页会话，释放资源。返回重进不恢复活跃回合；保留设置和已保存名单。

## 12. 状态接口约定

CoinState 至少包含 phase、roundId、revealedSide；待揭晓结果保持 ViewModel 内部，不能在状态区提前展示。

requestFlip() 返回或发出含 roundId 与目标朝向的动画指令；接口具体形式可沿用工程状态管理习惯。动画参数可读取目标朝向，但 UI 文案只有在 reveal(roundId) 后显示结果。

reveal(roundId) 仅在 ID 匹配且本轮运行时提交揭晓；finish(roundId) 仅在 ID 匹配时解锁。View 不自己重新生成随机结果。

每轮结束的累计角度保留在页面表现状态中；开始下一轮时以该角度为起点。减少动态效果也必须更新逻辑最终朝向，切回标准动画后不发生跳面。

SettingsState 至少包含 hapticsEnabled、motionSpeed、reduceMotion、appearance。设置更新与持久化不阻塞点击反馈，但错误需要被捕获。

计时会话包含 sessionId、phase、duration、elapsed、correctIds、skippedIds、activeWordId。显示剩余时间由有效活动时长推导，不维护另一个独立递减计数作为真值。

名单模型采用 Participant(id, name)，不要用姓名作为稳定 Key；题目采用稳定 ID，不用列表当前索引代表身份。

## 14. 计时与存储边界

抽题规则在类别内保持已用集合，重置当前会话时清空。若类别内只有 1 条，允许循环同题但应保持流程可用；种子数据正式验收应达到上述下限。

计时游戏倒计时显示采用向上取整的剩余秒数，结束判定使用精确有效剩余时长不大于零。显示数字只是表示层，不作为计分许可依据。

答对或跳过必须对当前词条进行一次性消费，快速双击不能给同一词条记两次。页面切换词条后才接受下一次输入。

结束动作具备幂等性；时间到与用户点击结束同一时刻发生，也只能结算一次。

持久化数据带基本 schema 版本，读取无效类型或损坏值时回退默认配置，不直接强制类型转换导致启动失败。

名单首次启动可以提供玩家1–玩家4，后续保留用户保存内容；不得每次打开编辑器都覆盖用户名单。

持久化失败有可理解提示，当前内存功能仍可使用。不要让外观更新等待磁盘写入后才响应。

首版不存储所有回合历史，只保留设置、外观与最近保存名单。
